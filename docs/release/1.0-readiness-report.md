## 2. Automated Crash & Failure Resilience Evidence (Criterion 4)

Executed via the Windows `TerminateProcess` crash runner (`crates/xtask` & `crates/core` fault injection hooks, commit `2c053ae`):

1. **Forced Kills During Payment Recording (`20 / 20 Passed`)**:
   - Injected deterministic fault checkpoints before and after SQLite WAL commits during `cashier.record_payment`.
   - **Result**: Every post-restart recovery passed `PRAGMA integrity_check`. Retrying with the same client `idempotency_key` produced zero duplicate payments and exact paisa ledger conservation.
2. **Forced Kills During Encrypted Backup Creation (`10 / 10 Passed`)**:
   - Terminated worker mid-stream while writing `.cbackup` staging files.
   - **Result**: Atomic staging-to-final rename ensured previously verified `.cbackup` archives were never overwritten by truncated files.
3. **Forced Kills During Schema Migrations (`10 / 10 Passed`)**:
   - Terminated worker mid-DDL/DML migration transaction.
   - **Result**: Transactional migration rollback left the database cleanly at the prior schema version and automatically triggered the pre-migration backup safety net.
4. **Environmental Fault Simulation (`Low Disk, USB Disconnect, Clock Jump`)**:
   - Simulated `< 50 MB` free disk space, sudden removal of destination backup path, and backward system clock jumps (`acknowledge_clock_jump`). All scenarios surfaced structured `{ code, params, field }` domain errors without panics.
